## A. 安全与隐私（P0，最高优先级）

### A1. 威胁模型
| 资产 | 威胁 | 对策 |
|---|---|---|
| 浏览者浏览器/数据 | XSS、第三方脚本、跟踪、恶意链接 | 全部外源数据转义渲染；CSP；无第三方脚本/字体/CDN；无分析/埋点；外链 rel=noopener；禁止 javascript: |
| 用户输入的 API Key（BYOK） | 泄露、误上传、日志记录 | 仅 localStorage；不上传本站；不写日志/不注入 prompt 上下文；设置面板可清除；显式隐私说明 |
| 项目仓库/维护者本机 | 个人信息（用户名/本地路径/凭据）泄露、供应链攻击 | 仓库 PII 扫描与清理；Actions 固定到 commit SHA；最小权限；SECURITY.md + 报告渠道；Dependabot/CodeQL |
| 数据源内容 | 恶意/畸形内容注入（RSS/HTML/JSON） | 采集端去标签/转义；前端 `esc()`/textContent 渲染；长度/大小限制；URL scheme 白名单 http(s) |
| 分享/传播 | 卡片/链接伪造、隐私泄露 | 卡片不含个人数据；分享 URL 仅站内；OG 无用户数据 |

### A2. 代码与页面安全要求（必须逐项落实）
1. **XSS**：所有外部数据（news/models/rankings/skills/topics/meta）必须经 `esc()` 或 `textContent` 渲染；禁止 `innerHTML` 拼接未转义变量；Markdown-lite 仅允许 http(s) 链接且先转义；URL 参数（`?tag=`/`?lang=`/`?theme=`）白名单校验后再使用；分享文案/卡片文本用 canvas 文本 API（安全）。
2. **CSP**：所有 HTML `<head>` 增加 `<meta http-equiv="Content-Security-Policy" content="default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self' https:; font-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-src 'none'">`（GitHub Pages 不支持 headers；meta 为最佳可用手段；`connect-src https:` 为 BYOK 兼容所必需）；另加 `<meta name="referrer" content="no-referrer">`、`<meta name="robots" ...>` 保持现状。
3. **外链**：所有 `target="_blank"` 必须有 `rel="noopener noreferrer"`；仅允许 `http(s):`；禁止 `javascript:`/`data:` 链接。
4. **BYOK 隐私**：key 仅 localStorage（key 名固定）；不 console.log key/config；不上传本站；不进入站点上下文（buildContext 只放公开数据）；设置页提供「清除密钥/清除会话」；文档明示风险；页面无任何第三方脚本/统计/像素。
5. **依赖与供应链**：运行时零依赖；Actions 全部固定到 **commit SHA**（含 checkout/setup-node/configure-pages/upload-pages-artifact/deploy-pages/codeql），并注释版本；workflows 最小权限（默认 contents: read，部署 job 才 pages:write/id-token:write，refresh 才 contents:write）；禁止 `pull_request_target`；新增 `codeql.yml`（javascript）与 `dependabot.yml`。
6. **仓库隐私**：全仓扫描并清除个人信息（本机用户名/路径 `C:\Users\...`、`D:\...`、token/密钥/内网 IP/邮箱）；文档中的环境说明改为通用描述；提交历史含旧 PII 的处置见 A4。
7. **可用性安全**：JSON 数据文件大小上限（单文件 ≤2MB，总 data ≤5MB）；解析失败降级；`?tag=` 长度限制；分享/复制不执行任意脚本；禁止 `eval`/`new Function`/`document.write`。
8. **安全交付物**：
   - `SECURITY.md`（威胁模型/报告渠道/响应时限/支持版本/隐私声明）
   - `docs/SECURITY-AUDIT.md`（审计方法、发现清单 严重级别 + 修复 + 残余风险 + 复测结果）
   - `scripts/security-check.mjs`（CI 可跑：PII 扫描、危险 API 扫描、外链 rel、CSP meta 存在、Actions SHA 固定、无 secrets、无 http://、data 大小；`--strict` 0 命中；`--self-test`）
   - `tests/security.test.mjs`（esc/markdown/URL scheme/JSON 注入/分享文本 XSS 向量）
   - CI 纳入 security-check + tests；CodeQL workflow。
9. **本地数据隐私**：脚本不读取/不写入工作区外文件；不上传任何本地数据；测试与截图不含真实 key/Token（只 mock）；`.gitignore` 覆盖 env/key/credentials；任何示例 key 使用占位符。

### A3. 第三方安全审计

## B. 功能与体验（P1）

### B1. 榜单 top10 + top3 标记 + 紧凑分发信息
- 每个榜单显示 **Top10**（现有 entries 可全量；默认展示前 10，提供「展开全部」）。
- 1/2/3 名加标记：`🥇/🥈/🥉` 风格但用**主题内敛样式**（金色/香槟/石墨色徽章 + 序号），不引入 emoji 外链；`aria-label` 含名次。
- 榜单卡/分享卡：**分发信息极简**——底部一行细 strip：小 logo + `chengxi-z.github.io/llm-pulse` + GitHub 短地址 + 小二维码（≤64px）；高度 ≤ 卡片 12%，与主内容有 1px 线分隔；"肉眼可辨但不起眼"。
- 榜单页每榜「分享本榜」沿用。

### B2. 模型对比（任意 N，真实评分）
- 入口：`models.html` 增加「对比」能力：模型卡/表格行复选框，底部浮动对比栏（已选 N/最多 6），点「开始对比」打开对比视图（modal/独立区域）。
- 对比字段（全部真实数据，缺失显示 `—`）：
  - 能力评分：Artificial Analysis 智能指数（主，匹配到即显示）、LMArena/LiveBench/Epoch/OpenCompass 分数（按模型名归一化匹配，若无则不显示该列值）；分数带来源与口径 tooltip。
  - 价格：输入/输出 $/1M；上下文窗口；模态；开源权重/许可证；发布日期；厂商。
- 名称匹配规则：去括号变体/厂商前缀/标点，需在页面注明「评分按模型名匹配，未匹配显示 —，不编造」。
- 交互：键盘可达、移动端横向滚动、清空/移除单个/分享对比结果（可选）。
- 数据：无需新数据文件；从 models.json + rankings.json 客户端匹配（写 `data-match.js` 纯函数，可单测）。

### B3. 斩杀线 2.0（能力 × 成本）
- 新图：散点图 **x=输出价格（log，$0.01–$100+），y=Artificial Analysis 智能指数（或备选 Epoch ECI）**；仅绘制「有评分且已匹配价格」的模型（按名称归一化，当前 CI 数据 91 榜中匹配 ~83 个）。
- **两条斩杀线**：能力斩杀线 = 评分中位数（P50，水平虚线）；成本斩杀线 = 价格中位数（垂直虚线）；交点划分四象限，**左上=高能低价（生存区）**，其余标注为「斩杀区/高成本区/低能力区」。
- 点：按厂商着色（或统一主题色 + hover 显示模型/分数/价格）；生存区模型加大/金色描边；tooltip：`模型 · 分数 · $价格`；键盘可聚焦。
- 文案：规则、样本量（`N 个已匹配模型`）、「非质量/推荐评价」免责；无评分模型不绘制并说明。
- 数据：客户端从 rankings(AA) + models 匹配（共用 B2 的匹配函数）。
- 若 AA 无数据或全未匹配：显示降级空态（提示数据源状态）。

### B4. AI 话题热榜 2.0（真实热搜话题 + 讨论摘要）
- 新数据文件 `data/topics.json`（schema 见 DATA-CONTRACT §6.2）：由数据管道从 **Hacker News Algolia API**（公开、无需 key；`https://hn.algolia.com/api/v1/search`）抓取近 7 天 AI 相关故事（score/points≥30），按 points 排序取 Top 10；每条：`title, url, domain, points, comments, publishedAt, summary`（讨论摘要取该故事首条高赞评论纯文本 ≤160 字符，HTML 清洗；拿不到则用标题+来源说明），`source: "Hacker News"`。
- 仪表盘「AI 话题热榜」改为真实话题列表：名次 + 标题 + 摘要（1-2 行 clamp）+ `🔥 N points · M comments` + 来源域名 + 时间；点击外链（`rel="noopener noreferrer"`）；口径注明「Hacker News 近 7 天 AI 相关讨论，非全网热搜」。
- 保留 `news.html?tag=` 深链功能（从站内标签跳转），热榜不再用关键词统计。
- CI 侧抓取（Actions 网络通畅）；本机若不可达则保留最近快照并标注 degraded；无数据空态。
- 数据管道更新 `meta.sources` 增加 `hn-ai` 状态。

### B5. 引导页/hero 瘦身（内容优先）
- 所有页面 masthead/hero 高度压缩：标题字号降一档、lede 最多 2 行（clamp）、统计/eyebrow 同行或紧邻；首屏内必须能看到**内容主体**（榜单表格/模型卡/技能卡/资源列表/项目卡）至少 1 行/1 卡。
- 度量（审计新增）：在 1440×900 视口下，各页面「第一个内容卡片/表格行」顶部 ≤ 620px；移动 390×844 下首个内容卡可见（顶部 ≤ 视口 75%）。
- 首页 hero 保留品牌感但压缩高度（目标 ≤ 560px @1440）。

### B6. 图表动态轮播
- 仪表盘图表区改为**自动轮播**：4 个视图（发布柱状图 / 价格环形饼图 / 斩杀线散点 / 话题热榜）轮流展示，或 2-3 个图表 + 热榜独立；默认每 **6.5s** 自动切换，柔和滑动/淡入（≤600ms，ease-out），**允许比此前略明显的动效但必须柔和**（无弹跳、无闪烁）。
- 控件：圆点/进度条、左右箭头（可选）；hover/focus 暂停；用户手动切换后暂停自动一段时间（如 12s）；移动端支持滑动；`prefers-reduced-motion` 关闭自动轮播（手动切换）。
- 轮播异常/无 JS 时：至少显示第一个视图（渐进增强）；面板高度固定避免跳动。
- 体积：dashboard.js 增幅记录（当前 27.2KB，预算放宽至 34KB 需记录）；CSS 拆分保持。

### B7. 分享卡分发信息极简
- 分享卡（news/board/skill/site）底部地址区改为**极简 strip**：小 logo + 站点 URL（≤16px）+ GitHub 短地址 + 二维码 56-64px（右侧），总高 ≤ 卡片 12%；保留对比度 ≥4.5:1；榜单卡 Top3 名次加徽章标记。
- 站内「品牌分享卡」预览同步。
