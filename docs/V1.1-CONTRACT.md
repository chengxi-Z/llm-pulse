## 2. UI：多主题设计规范（R1）

### 2.1 主题清单（`<html data-theme="...">`）
| id | 名称 | 气质 | 背景/表面 | 主色 | 强调 |
|---|---|---|---|---|---|
| `ivory` | 纸墨雅金（默认） | 米白纸感、衬线、香槟金 | #F6F1E9 / #FFFDF9 | ink #14100C | gold #B08A4F · 墨绿 #12312A |
| `noir` | 深夜鎏金（暗） | 黑金、博物馆夜展 | #0E0D0B / #171411 | #F2ECE2 | gold #C9A227 |
| `jade` | 青瓷墨绿（浅） | 青瓷、茶室、清冷高级 | #F3F5F1 / #FBFCF9 | #17211B | jade #3F6B57 · 金 #A98C55 |
| `rose` | 暮云玫瑰（浅） | 暮色、香槟粉、柔奢 | #F7F1EF / #FFFCFB | #1D1517 | mauve #9A6B74 · gold #B08A4F |
| `graphite` | 极简石墨（浅/中性） | 建筑感、冷灰、克制 | #F3F2EF / #FAFAF8 | #171717 | 银灰 #8C8A85 · 墨 #2A2A28 |
| `auto` | 跟随系统 | 由 prefers-color-scheme 在 ivory/noir 间切换（仅此二主题参与 auto；手动选其它主题则为固定主题） |

规则：**所有颜色必须来自 tokens**（禁止组件内硬编码十六进制，主题才能在 5 套间完整切换）；5 套主题的正文对比度均 ≥4.5:1；金色大字仅用于装饰性/展示性文本时允许 <4.5:1，但需同时提供 ink 色可读版本。

### 2.2 主题技术契约
- 状态：`document.documentElement.dataset.theme = "ivory|noir|jade|rose|graphite"`；`data-theme-source = "manual|system|url"`。
- 持久化：`localStorage["aipulse.theme"]` ∈ {ivory,noir,jade,rose,graphite,auto}（默认 `auto`）；URL `?theme=<id>` 优先且不写 localStorage（分享用）。
- 防闪烁：各页 `<head>` 内联脚本在 CSS 前计算并设置 `data-theme`（现有脚本扩展，不得引入外链/异步）。
- `<meta name="theme-color">` 随主题更新。
- 选择器：header 内 `.theme-picker` 按钮（图标=调色/太阳）＋ popover `.theme-menu`，含 6 个选项（5 主题 + 跟随系统）与色板预览点；键盘可操作（Enter/Space 打开、方向键移动、Esc 关闭）、`aria-expanded`/`role="menu"`/`aria-checked`；移动端同 popover 或底部 sheet，不引入第三方库。
- 组件不得依赖 `prefers-color-scheme` 媒体查询做颜色（除 `auto` 解析为 ivory/noir 的两套 token 外）。

### 2.3 按钮色彩（用户反馈：太深）
- 新增 token：`--btn-primary-bg`（默认 `var(--gold)`）、`--btn-primary-fg`（默认 `var(--ink)`）、`--btn-primary-border`、`--btn-primary-bg-hover`、`--btn-secondary-bg`（透明）、`--btn-secondary-border`（gold hairline）、`--btn-secondary-fg`；每主题可覆盖。
- 主按钮：金色/主题主色填充 + 深色文字，**禁止大面积纯黑填充**；hover 加深/描边；active 轻微内影；focus-visible 金线外环；disabled 降透明度。
- 深色主题（noir）主按钮：金填充+ink 文字（保持亮），或 ivory 描边按钮，不得用重黑。
- 全站按钮 4 态（hover/active/focus/disabled）与对比度必须验收。

### 2.4 回顶按钮（back-to-top）
- 由 `app.js` 统一动态创建（各页无需改 HTML）：`<button class="to-top" data-to-top aria-label="回到顶部" title="回到顶部">`，内为 ↑ 或 SVG 箭头。
- 行为：滚动 > 600px 淡入（opacity/translate），点击 `window.scrollTo({top:0,behavior:smooth})`（`prefers-reduced-motion` 用 auto）；位置右下角、在 AI 助手按钮上方错位（两者不得重叠，移动端安全区）；z-index 合理；键盘可聚焦。
- 样式由 CSS token 驱动；i18n key：`ui.toTop`（aria-label/title）。

### 2.5 滚动条美化
- WebKit：`::-webkit-scrollbar{width:10px;height:10px}`、track 透明、thumb 圆角渐变（`--gold-soft`→`--gold`，暗色用 `--line`→`--gold`）、hover 加深；Firefox：`scrollbar-width: thin; scrollbar-color: var(--gold-soft) transparent`；不得影响横向表格内部滚动条（表格容器单独保持可用）。

### 2.6 其它 UI 优化（UI 设计师可自主，需写入 UI-SPEC）
- 移动端 header 更紧凑、主题/语言入口同排；hover 状态统一；卡片层级与留白微调；表格在窄屏的可用性；加载/空态更精致；暗色下图片/图表可读性；`@supports` 降级。
- 性能：CSS 增量后全站 raw CSS ≤120KB（gzip ≤25KB）；不得新增外链资源/字体/图片。

## 3. 国际化（i18n）契约（R2）

### 3.1 文件与接口
- 词典：`site/assets/i18n/zh.json`、`site/assets/i18n/en.json`（扁平点分 key，例：`nav.home`、`home.hero.title`、`news.filter.all`；禁止嵌套对象，便于校验/翻译）。
- 引擎：`site/assets/js/i18n.js`（ESM，site-mvp 实现）：`load(lang)`、`t(key, vars?)`、`setLang(lang)`、`getLang()`、`applyDom(root=document)`、初始化（读取 localStorage→URL `?lang=`→默认 zh）。
- 页面挂钩（site-mvp 负责）：
  - 静态文案：`data-i18n="key"`（textContent）；属性用 `data-i18n-attr="placeholder:news.search.placeholder,title:..."`（逗号分隔 `<attr>:<key>`）；禁止 `data-i18n-html`（避免 XSS）。
  - 动态渲染（render.js）：所有标签/按钮/空态/日期词使用 `t()`；数据原文（模型名、来源名、新闻标题）保持原样。
  - `<title>` 与 meta description 由词典 key 设置（`page.news.title` / `page.news.desc`）。
- 切换控件：header 内 `.lang-toggle`（文本「中 / EN」或地球图标 + 当前语言），`aria-label`、键盘可用；切换后即时应用、`html.lang` 更新、`localStorage["aipulse.lang"]` 持久化、页面不刷新、URL 不强制改写（可用 `?lang=` 深链）。
- 防闪烁：`<head>` 内联脚本按 lang 设置 `document.documentElement.lang`；英文首屏可接受极短原文（不阻塞）。
- 首屏默认：中文（`zh`）；`navigator.language` **不**自动切英文（用户要求中文默认）。

### 3.2 词典校验（i18n-en 负责脚本与词典）
- `scripts/check-i18n.mjs`：扫描所有 `site/*.html` 的 `data-i18n`/`data-i18n-attr`、`site/assets/js/**` 的 `t('...')` 字面量，与 zh/en 词典比对；输出缺失/多余/空值；`--strict` 任一缺失即退出码 1；CI 必跑。
- 词典要求：zh/en key 集合完全一致、无空字符串、en 无中文残留（专有名词/中文品牌名除外，白名单 `scripts/i18n-allowlist.json`）；`node scripts/check-i18n.mjs --strict` 通过。
- 覆盖范围：7 页 + 404 + 助手 UI + 分享文案 + 空态/错误态 + 数据源状态 + 订阅区 + 页脚 + 主题选择器 + 回顶 aria + 排行表头/指标/更新时间词；约 250-350 keys。
- 数据侧：榜单显示名/描述在 en 词典以 `board.<board-id>.name/.desc` 映射，缺失回退中文原文（允许，属数据边界）；日期/数字用 `Intl.DateTimeFormat(locale)`、`Intl.NumberFormat(locale)`。

### 3.3 英文模式内容规则
- UI 100% 英文；新闻标题/摘要保留原文语言（来源原文，不机翻，属数据边界）；学习资源与项目描述保留中文（数据侧内容，英文模式不翻译，可后续由数据管道补 `descriptionEn`）。
- 英文模式页面标题/描述全英文；404 文案英文。

## 5. 一句话交付 Skill（R4，重点工作）

### 5.1 定位
把「用户一句话需求 → Lead 标准/分工/契约 → POC → MVP → GitHub 发布 → 验收报告」这套在真实项目中跑通的方法论与提示词固化为**可复用 Agent Skill**：给定一句话（例："帮我做一个持续追踪某领域公开动态的公域轻奢网站，含 AI 助手和自动更新"），Agent 按 Skill 流程产出可上线项目骨架、数据管道、验收证据与发布动作。

### 5.2 目录与文件
```
skills/
├─ README.md                          # Skill 索引与维护说明（英文）
└─ one-sentence-project/
   ├─ SKILL.md                        # 必需；YAML frontmatter: name, description；正文英文
   ├─ references/
   │   ├─ requirements-template.md    # 需求/SPEC 模板（目标/非目标/验收）
   │   ├─ data-contract-template.md   # 数据合约模板（schema v1）
   │   ├─ acceptance-checklist.md     # 三层验收清单（POC/MVP/Release）
   │   ├─ data-source-strategy.md     # 数据源矩阵/双模式/降级/合规
   │   └─ design-tokens.md            # 轻奢多主题 token 规范（5 主题）
   ├─ scripts/
   │   ├─ scaffold.mjs                # 生成项目骨架（docs/templates + data 空合约 + 目录 + package.json + gitignore）
   │   └─ check-project.mjs           # 校验骨架/成品是否满足 Skill 验收（文件/合约/页面/测试）
   └─ examples/
       └─ prompts.md                  # 可复制的一句话提示词示例（不同领域适配）
```
### 5.3 SKILL.md 必须包含
- `name`（kebab-case，如 `one-sentence-project`）、`description`（何时使用、能力边界一句话，供 Agent 检索加载）；建议同时提供中文触发示例。
- **When to use / not use**（触发与边界）；
- **Input contract**：一句话需求最少需包含的信息（领域、要追踪什么、展示形态、发布目标）；缺信息时的澄清问题模板（≤3 问）；
- **Workflow**（分阶段 + 门禁）：Standard → Contract → Team/Task split → POC gate → MVP → Release (GitHub/Pages) → Acceptance/Report；每阶段产出物与 Exit criteria；
- **Quality gates**：数据不造假、来源可追溯、双模式数据源、合约校验、浏览器验收（CDP/headless）、性能预算、a11y、i18n、安全（无密钥入库/BYOK）；
- **Value**（体现亮点）：一句话→可上线数据站；沉淀踩坑经验（GFW 双模式/镜像、静态优先、BYOK、Actions 自动刷新、验收方法论）；可迁移到任意"持续追踪公开信息"的领域；
- **Boundaries**（边界，必须如实）：非通用 Web 框架/无后端/无账号/无实时高频；依赖 Node≥20、GitHub、数据源公开与合规；AI 助手需用户自备 key+CORS；审美与内容需人工复核；多智能体团队为可选增强（单 Agent 可用同一流程）；
- **Examples**：3 个一句话示例 + 产出物清单；
- **Anti-patterns**：先写页面后定数据、伪造榜单、忽略降级、只截图不验收、密钥入库等。

### 5.4 自检与纳入 CI
- `node skills/one-sentence-project/scripts/check-project.mjs --self` 校验 Skill 包完整性（frontmatter/文件/可解析）；
- `node skills/one-sentence-project/scripts/scaffold.mjs <tmp-dir> --name demo --domain "LLM tracking"` 能在临时目录生成骨架，且 `check-project.mjs <tmp-dir> --skeleton` 通过（CI 中跑）；
- Skill 文本中的路径/命令必须与仓库实际一致（由 check 脚本断言关键文件存在）；
- README 增加「Skill：一句话交付」章节（中文）+ README.en.md 对应章节，讲清价值与边界（用户要求）。
